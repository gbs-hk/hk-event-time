# Accessibility Checks

Accessibility is checked with pa11y against the locally served Flask homepage.

## CI Policy

The GitHub Actions workflow [`.github/workflows/accessibility.yml`](../.github/workflows/accessibility.yml) runs on pull requests, pushes to `main`, and manual dispatch.

The check fails on any pa11y `error` with a zero threshold:

```bash
npx --yes pa11y http://127.0.0.1:5050/ --level error --threshold 0
```

One known FullCalendar-generated issue code is temporarily ignored:

```text
WCAG2AA.Principle1.Guideline1_3.1_3_1.F92,ARIA4
```

That exception is tracked as Azure DevOps defect `#46`. Remove the ignore once that defect is fixed.

## Local Run Before PR

From the repo root:

```bash
source .venv/bin/activate
pip install -r requirements.txt
FLASK_ENV=production PORT=5050 SCRAPE_INCLUDE_SAMPLE=1 python run.py
```

In another terminal:

```bash
npx --yes pa11y http://127.0.0.1:5050/ \
  --level error \
  --threshold 0 \
  --ignore "WCAG2AA.Principle1.Guideline1_3.1_3_1.F92,ARIA4"
```

Run the normal Python tests too:

```bash
python -m pytest
```

## When UI Changes

- Confirm keyboard focus is visible.
- Check dialogs restore focus after closing.
- Keep `#calendarStatus` as a polite live region.
- Do not rely on color alone for event categories.
- Re-run pa11y after changing FullCalendar config, category colors, dialogs, or controls.
